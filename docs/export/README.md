## 关键防误读
- MRR、近30天收入和累计收入是三个不同量。收入不是利润，也不能证明少量推广就有客户。目录中2家平台显示GMV而非累计收入，且首页公开JSON-LD把它们的近30天指标明确标成GMV（与目录通用Revenue列标题冲突）。因此GMV分别保存为 metrics.gmv_30d / metrics.gmv_total，近30天营业收入和累计营业收入都保留未知；原目录快照仍完整保留。
- 目录金额是展示值，可能四舍五入；`$1.2K`只换算为数值1200，同时保留原文及 precision；不是精确账本。
- 档案收入是TrustMRR宣称经支付商API核验的公开快照；我们没有独立查账。产品功能/客群/价格/渠道/技术栈多为创始人自填，不能等同API核验。
- `null`/未知 ≠ 0；零收入明确保存为0。不因为非网页、API成本高、匿名或信息少就删除。
- 类别只引用TrustMRR原始 Markets 或公开推荐的 category；没有就未知，不凭名称猜。
- `founded_date`是成立日期，不是上线日。`launch_date`仅在有明确自述引用时填写（含只精确到月的字符串），上线证据本身仍非独立审计。
- 不同TrustMRR slug即使品牌相同也保留，不擅自合并App版本/多个商户档案。Stealth Company / Paddle Business 等匿名占位记录也保留。
- 成本、利润、API支出、获客成本、网页属性没有核实的一律未知。本包不生成全项目人工估算，不代表投资推荐。
- 核验级别 O=之前读过官网正文；P=实际读公开档案；D=只见正常目录；R=只见已读公开档案的推荐卡。O/P不是收入更高或更值得做的评级。
- source_url/read_at 是相应来源和读入时点；旧缓存时点以文件mtime近似并标注 read_at_basis。收入同步时点另看 revenue_synced_at / metrics.*.synced_at。原始ISO时戳自带UTC时区；面向人报告时转换北京时间。
